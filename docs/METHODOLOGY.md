# 估價方法論

這份文件記錄 `data/vehicles.json` 裡的數字是怎麼來的。要新增車款、更新行情、
或判斷某個數字可不可信，先讀這裡。

要餵給 agent 的規則原文在 `docs/agent-rules.md`，那份可以直接貼進 prompt。

## 成本模型

一台車的持有成本只有三項：

```
總成本 = 折舊 + 保養 + 賣出費用
       = (實付車價 − 該年殘值) + 累計保養 + 過戶整備費
```

**稅金與保險刻意不計。** 它們幾乎只跟排氣量、車價、車主年齡有關，跟「這台車值不值得買」
沒有鑑別度，放進來只會稀釋掉真正有差異的部分。油錢與停車費同理不計。

折舊是主體。實測 114 台的結果，折舊佔總成本 **69%–90%**，保養佔剩下的部分。
所以選車時二手保值率的權重，應該遠高於保養便宜與否。

## 買家設定：一年 6,000–8,000 km

這個設定不是背景資料，它實質改變每一個數字：

| 影響 | 說明 |
|---|---|
| 里程假設 | 每個檢查點一律 `assumed_km = 7000 × 年數`，即 7k / 21k / 35k / 49k / 70k |
| 查行情要挑低里程件 | 台灣平均一年跑 12,000–15,000 km，這個買家只有一半。同年份的車，他的里程會落在「低里程帶」，成交價高於里程盲的市場平均 |
| 保養是「時間到」不是「里程到」 | 多數品牌的保養間隔是「1 萬公里或 12 個月，先到為準」。一年 7,000 km 永遠是時間先到，所以一年進廠一次，跑不到里程觸發 |
| 耗材是老化不是磨耗 | 輪胎約 5–6 年因橡膠老化換掉，不是磨平；碟盤可能因為用得少而先鏽蝕劣化 |
| 保固是被時間吃掉的 | 例如「8 年或 16 萬公里」的電池保固，這個買家十年也才 7 萬公里，所以永遠是第 8 年時間到期 |

最後一點造成一個反直覺的結果：**Volvo XC60 T8 插電式油電第 10 年的絕對殘值，
低於便宜 60 萬的 B5 汽油版。** 電池保固被時間吃掉，最後兩年裸奔，買家直接砍價。
低里程救不了按日曆老化的電池。

## 五階段工作流

每一批車都跑同一條流水線。四批（初始 17 台、Lexus 全系列、日系＋Tesla、德系）都是這個結構。

```
Scout ──► Research ──► Verify ──► Cross-check ──► Repair
 抓車型     查行情      對抗式查核    橫向比對       重做
```

### 1. Scout — 不要憑印象列車型

派 agent 去官網把**現行在台販售**的車型與牌價抓下來，再依實際結果 fan out。

為什麼重要：憑印象列會編出不存在的車型，也會漏掉真的有賣的。實測 scout 抓到我原本
不知道的 **Lexus ES500e 純電版**與 **NX350 Overtrail 版**；德系三品牌 scout 出 54 個車型，
比我憑印象估的多了一半。

Scout 的產出要帶 `source_url`，那是它真的打開過的頁面。

### 2. Research — 一台車一個 agent

每個 agent 只負責一台車，查官網牌價、8891／SUM 中古行情、Mobile01 保養實單，
產出完整記錄。規則見 `docs/agent-rules.md`。

### 3. Verify — 對抗式查核

**這步不能省。** 派第二個 agent，明確告訴它「預設前一個 agent 寫錯了，去找出來」，
獨立重查一次牌價與行情。

實測抓到的真錯誤：把車商開價當成自售價、trim 階梯反轉、保養費方向錯（貴的 trim 比便宜的
還低）、動力別排序破功。單靠一個研究 agent 這些都會漏掉，因為它自己看不出自己的盲點。

### 4. Cross-check — 橫向比對

一個 agent 同時看**多台車的完整曲線**，抓「單獨看每台都合理、擺在一起卻互相矛盾」的錯。

這是前面三步結構上做不到的事：每個 research agent 都被隔離在自己那台車裡，看不到別人。

實測抓到：Tesla 殘值被高估到贏過所有德系（與台灣實況相反）、Lexus RX350 汽油版在第 10 年
反超油電版（方向錯）、Audi Q5 被填成全組最極端值（但它才剛上市根本沒有長期資料）、
Porsche 保養費算得比 Volvo 還輕。

比對的判準依範圍不同：

| 比對範圍 | 判準 |
|---|---|
| 同車型不同 trim | 保值「率」隨 trim 上升而微降，但**絕對殘值必須仍然較高** |
| 同品牌不同車型 | 動力別排序、級距邏輯（SUV 優於同價轎車）、保養隨車體大小遞增 |
| 跨品牌 | 台灣市場已知排序：Alphard／LM ≫ Lexus 油電 > Toyota > 德系 > 純電 |

### 5. Repair — 只重做被點名的

拿著 cross-check 的具體指控去重查，其他沒被質疑的部分保留。

## 最關鍵的一條規則：車商開價不是你賣得到的錢

這是整套方法最容易錯、錯了最致命的地方。價格鏈是：

```
車商售價（8891 上看到的）  >  自售價  >  車商收購價
                    低 8-15%      再低 10-15%
```

`private_sale_price` 必須是**自售價**。直接把 8891 的車商開價填進去，
會高估殘值約 10%，整個成本模型就廢了 —— 而且不會有任何欄位報錯，它只是安靜地錯。

每筆估價的 `source` 欄位要寫明做了什麼換算。

## 7 年與 10 年怎麼來的

這 114 台幾乎都是現行世代新車，市場上**不存在** 7 年以上的成交紀錄。做法是：

1. 找上一代車型在該車齡的真實中古行情
2. 換算成「佔它自己當年牌價的百分比」
3. 把這個保值率套到這台車的實付價上
4. `source` 寫明是外推，`confidence` 標 `low`

**明講外推是可以的，安靜編造不行。** 570 個估價點裡 328 個是 `low`，集中在 7／10 年。

實務判準：**這些數字拿來排序、比高低可靠；拿單一絕對值當精算基礎不行。**

## 動力別分類

分類錯會讓整個動力別分析失真，而且很難察覺。

| 分類 | 判準 |
|---|---|
| `gasoline` | 含 48V 輕油電（B3/B4/B5、eTSI、EQBoost、MHEV）—— **不能純電行駛就不算 hybrid** |
| `hybrid` | 完整油電，可以純電推動車輛（Toyota HEV、Lexus h） |
| `phev` | 插電式（T8、450h+、TFSI e、xDrive e） |
| `bev` | 純電 |
| `diesel` | 柴油 |

曾經發生過：Volvo B3/B4/B5 在不同批次被標成 `hybrid` 和 `gasoline` 兩種，
同一種東西分成兩類。修正時要順便掃全庫確認沒有別的品牌也踩到。

## 衍生欄位不要手算

`retention_ratio`、`depreciation_amount`、`cumulative_cost`、整個 `cost_summary`
都由 `validate.py` 算。agent 只填原始數字。

```sh
uv run --quiet --with jsonschema python validate.py data/vehicles.json --fix
```

`--fix` 重算並寫回；不帶 `--fix` 只檢查。它還會驗 schema 沒辦法表達的規則：
檢查點年份遞增、里程等於 7000×年數、殘值嚴格遞減、購入價算式正確。

## 新增車款的流程

1. Scout 該品牌官網確認車型與牌價（不要憑印象）
2. Research + Verify 兩道 agent
3. 合併進 `data/vehicles.json`，移除衍生欄位
4. 跑 `validate.py --fix`
5. Cross-check（跨車款橫向比對）
6. 瀏覽器開頁確認呈現正常

第 5 步目前在 114 台裡大部分還沒做，見 `TODO.md`。

## 這套方法的已知弱點

**行情是掛牌價不是成交價。** 8891 上看到的是賣方開價，真實成交還會再低一些。
自售價換算已經吃掉一部分，但這不等於實際成交紀錄。

**保養是推估不是帳單。** 除了少數有 Mobile01 實單的車款，多數是照原廠保養表加上
耗材老化時程推算的。過保後的維修準備金更是機率加權的估計，不是報價。

**折讓幅度會變。** 各品牌的現金折讓隨月份、庫存、改款而動，記錄的是查證當下的合理值。

**時間會讓資料過期。** 每筆都有 `as_of`，大約一年該回頭更新一次 1 年與 3 年的點，
那兩個點才是有實際掛牌資料支撐的。
